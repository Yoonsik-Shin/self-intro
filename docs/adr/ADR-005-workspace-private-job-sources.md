# ADR-005: Workspace 비공개 채용 공고 원본

## 상태

Accepted — 2026-08-12. 운영 배포 전 로컬 검증 단계다.

## 맥락

채용 공고 원문은 플랫폼 공통 카탈로그와 사용자가 개인적으로 확보한 원본이라는 서로 다른 소유권을
가진다. 기존 `job_posting` 전역 URL 유일성과 운영자 ingest API를 일반 사용자 흐름에 그대로 쓰면,
미승인 외부 원문이 공통 자산처럼 보이거나 다른 Workspace와 충돌한다.

## 결정

- 권한 증빙이 승인된 플랫폼 원본만 `scope_key=PLATFORM` 공통 카탈로그로 조회한다.
- 사용자의 URL·직접 입력 원본은 `owner_workspace_id`와 `scope_key=WORKSPACE:{id}`로 소유권을 고정한다.
- URL 유일성은 전역이 아니라 scope 안에서만 보장한다.
- URL 해석은 Workspace 쓰기 권한을 검사하는 parse-only API로 수행하고, 검토 후 별도 저장한다.
- 지원 건을 삭제해도 비공개 원본은 보존한다. 같은 URL 재등록은 기존 원본을 갱신해 다시 연결한다.
- 스크린샷은 Workspace 전용 임시 업로드 티켓으로만 받는다. 티켓은 30분 후 만료되고 실제 객체의
  MIME·크기를 서버에서 다시 검증하며, AI 해석에는 서버 내부 바이트만 전달한다.
- 해석 결과는 저장하지 않은 초안으로 반환하고 원본 이미지는 성공·실패와 관계없이 즉시 삭제한다.
  사용자가 제거한 파일도 즉시 취소하며, 남은 임시 객체는 주기 정리 작업이 재삭제한다.
- 플랫폼 운영 역할만으로 비공개 원본을 조회하거나 수정할 수 없다.

## 결과

같은 외부 URL을 여러 Workspace가 독립적으로 기록할 수 있고, 플랫폼 카탈로그·수집·중복 병합과
사용자 개인 기록이 분리된다. 대신 Workspace 삭제 시 원본도 함께 삭제되며, URL 없는 직접 입력은
자동 중복 판별하지 않는다.

## 검증

- V224 migration 및 복합 unique index 확인
- Workspace A/B 동일 URL 등록과 상호 목록·상세 격리
- 비공개 원본의 플랫폼 관리·AI 재수집 ID 경로 접근 차단
- 지원 목록 제외 후 동일 URL 재연결
- Workspace A가 발급한 스크린샷 티켓의 Workspace B 사용 차단
- 허용 MIME 불일치·8MB 초과·전체 25MB 초과 차단과 해석 후 임시 객체 삭제
