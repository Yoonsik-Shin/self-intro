# Self-Intro 제품 쇼케이스 경계

## 결정

공개 `/architecture` 경로는 단순 기술 명세가 아니라 **Self-Intro 제품 쇼케이스**로 사용한다.
제품 문제와 관리 흐름을 먼저 설명하고, 시스템 아키텍처는 이를 뒷받침하는 하위 섹션으로 둔다.

경력이 늘어나 Self-Intro 프로젝트가 메인 프로젝트 목록에서 제외되더라도 제품 쇼케이스의 고유
URL은 유지한다. 현재 URL은 외부 링크 호환성을 위해 그대로 두고, 프로젝트가 여러 개가 되는
시점에 `/products/{slug}`를 정식 경로로 추가한다.

## 콘텐츠 경계

| 개념                 | 책임                                                         | 수명 주기                            |
| -------------------- | ------------------------------------------------------------ | ------------------------------------ |
| `Experience`         | 이력서에 사용하는 검증된 경험·성과                           | 경력 관리 정책에 따라 노출 여부 변경 |
| `PortfolioCaseStudy` | 특정 Experience의 문제·판단·해결·성과를 버전으로 발행        | Experience에 연결된 독립 공개 문서   |
| Product Showcase     | 제품 개요·사용 흐름·관리자 체험·운영 구조를 묶는 영구 페이지 | 메인 노출과 무관하게 유지            |
| Architecture         | 제품을 구현한 기술적 근거                                    | Product Showcase의 하위 섹션         |

아키텍처를 새로운 최상위 Aggregate로 만들지 않는다. 현재
`ArchitectureOverviewRepository.findFirstOverview()`와 전역 `ArchitectureLayer`는 단일 제품만
있는 동안의 호환 모델로 유지한다. 새로운 제품 쇼케이스가 필요해질 때
`PortfolioCaseStudy`의 slug·상태·revision 구조를 일반화한 `ProjectShowcase`로 통합하고, 기존
아키텍처 데이터는 해당 쇼케이스 revision의 `ARCHITECTURE` 섹션으로 이관한다.

화면만 정리한 현재 단계에서 빈 도메인 테이블을 먼저 만들지 않는다. 멀티테넌트 전환과 제품
쇼케이스 콘텐츠 모델은 서로 다른 결정이다. Workspace 도입은
[`ADR-001`](./adr/ADR-001-saas-security-multitenancy.md)에서 확정됐으며, 제품 쇼케이스는 별도
publication 모델이 필요해지는 진입 조건까지 기존 호환 모델을 유지한다.

## 공개 워크스페이스 데모의 안전 경계

`/architecture/demo`는 실제 `/admin`을 공개하지 않는다. SaaS 사용자가 보는 경력 관리
워크스페이스와 서비스 소유자가 보는 운영 콘솔은 다음처럼 분리한다.

| 화면               | 사용자                  | 포함 기능                                                                          |
| ------------------ | ----------------------- | ---------------------------------------------------------------------------------- |
| Career Workspace   | 구직자·경력 소유자      | 경력 자산, 근거·학습 기록, 기술·역량, 이력서, 지원 현황, 공개 프로필               |
| Public Profile     | 채용 담당자·외부 방문자 | 사용자가 공개하기로 선택한 프로필·경력·프로젝트·역량                               |
| Operations Console | 서비스 소유자·운영자    | 시스템 상태, Grafana·ArgoCD, 방문 분석, 후원, 전역 분류 체계, 제품 아키텍처 콘텐츠 |

사용자 워크스페이스의 메뉴와 상단 도구 모음에는 Operations Console 기능을 노출하지 않는다.
현재 단일 사용자용 `/admin`은 운영 콘솔과 개인 경력 편집기가 섞여 있는 레거시 화면으로 보고,
SaaS 전환 시 두 애플리케이션 셸과 권한을 분리한다.

- 이름과 경력은 합성 데이터만 사용한다.
- 변경은 React 메모리 상태에만 존재하며 API를 호출하거나 DB에 저장하지 않는다.
- 새로고침 또는 초기화 시 원본 합성 데이터로 돌아간다.
- 삭제·업로드·외부 AI 호출·채용 공고 수집 등 비용 또는 외부 상태를 바꾸는 기능은 제공하지 않는다.
- 실제 SaaS 전환 전까지 데모와 관리자 인증 도메인을 연결하지 않는다.

## 다음 단계 진입 조건

다음 조건 중 하나가 생길 때 `ProjectShowcase` Aggregate를 구현한다.

1. 두 번째 제품 또는 프로젝트를 동일한 형식으로 공개한다.
2. 쇼케이스의 제품 개요와 관리 흐름을 관리자 화면에서 수정해야 한다.
3. 제품별 아키텍처와 데모 시나리오를 별도 revision으로 발행해야 한다.

다음 조건이 생길 때만 데모를 서버 샌드박스로 확장한다.

1. 이력서 조합·PDF 생성처럼 여러 화면을 잇는 실제 저장 흐름을 체험시켜야 한다.
2. 데모 세션 격리와 만료 후 초기화를 서버에서 보장할 수 있다.
3. Workspace·Member·CareerProfile의 테넌트 경계가 먼저 구현되어 있다.
