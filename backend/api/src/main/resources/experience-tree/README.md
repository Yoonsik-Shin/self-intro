# Experience Tree catalog

경험 트리의 상황·선택지·트레이드오프·오답·출처는 애플리케이션 코드와 함께 버전 관리되는
정적 카탈로그다. 실행 시 YAML을 검증한 뒤 DB에 멱등 동기화하고, 조회 결과는 Redis에 캐시한다.

## 파일 구조

- `{domain}/*.yaml`: 도메인별 상황과 선택지, 트레이드오프, 경고, 출처. 파일은 주제나 우선순위별로 나눌 수 있다.
- `topology.yaml`: 부모-자식 구조, 도메인 간 관계, 초기 Study 회고 연결

상황·선택지·경고에는 변경되지 않는 전역 `stableKey`를 사용한다. 키 이름 변경은 삭제와 신규
생성으로 인식되므로 표시 문구를 바꿀 때는 키를 유지한다.

## 수집 및 검증 기준

1. 반복해서 등장하는 구현 의사결정 상황을 먼저 정의한다.
2. 선택지를 최소 2개 두고 적용 조건, 회피 조건, 장단점, 운영 메모를 기록한다.
3. 성능·정합성·신뢰성·보안·운영성·유지보수성 측면에서 명백히 잘못되거나 위험한 접근을
   `warnings`에 실패 조건·결과·교정 방법과 함께 기록한다.
4. `VERIFIED` 상황에는 벤더 공식 문서, 표준, RFC, 원 논문 등 1차 출처를 최소 1개 둔다.
5. 확인 날짜(`accessedAt`), 검증 날짜(`verifiedAt`), 다음 검토일(`nextReviewAt`)을 기록한다.
6. 실제 경험은 본문에 복사하지 않고 `topology.yaml`의 `studyLinks` 또는 관리자 수동 링크로
   연결한다. 카탈로그 링크는 정적 데이터이므로 관리자 화면에서는 읽기 전용이다.

## 변경 절차

`ExperienceTreeCatalogTest`로 YAML 파싱, 키 중복, 최소 선택지·출처, topology 참조와 부모 순환을
검증한다. 애플리케이션 import는 MySQL advisory lock으로 다중 인스턴스의 동시 동기화를 막는다.
카탈로그에서 제거된 선택지의 수동 Study 링크는 상황 전체 링크로 승격하며, 제거된 상황은 즉시
삭제하지 않고 `DEPRECATED` 처리한다.
